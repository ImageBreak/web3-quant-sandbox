# 学习笔记:信号分析流水线全链路(score / confidence / 回退 / 失败注入)

> 来源:`src/dashboard/`(signal_analysis / kline_analysis / llm_signal / signal_eval)+ `src/risk/` + `src/backtest/`
> 记录于 lesson 分支学习过程。数值示例来自 `run_llm_signal_analysis('BTC')` 真实输出。

## 0. 总览:信号流水线

一条交易信号从数据到晋级决策,要依次经过**四个阶段**:

```
数据(K线/行情/恐贪/资金)
  → [A] 规则引擎基线:score 计算 → 信号档位 → confidence     (确定性,离线可重现)
  → [B] LLM 增强层:_call_llm → _merge_llm 合并与校验          (可选,未配置则跳过)
  → [C] 评估门禁:score_llm_signal 评分 + critical 一票否决      (验收,不合格 retest/reject)
  → [D] 回测验证:回撤/成本/风控检查 → 12 道准入门槛             (晋级 PROMOTE_RESEARCH / REJECT)
```

**贯穿主线(BTC 实测)**:`score=-10 → WEAK_SELL(偏空观望)→ confidence=12.0`。每阶段都会回扣这条主线。

**三个贯穿概念**:

| 概念 | A 规则基线 | B LLM 增强 | C 评估门禁 | D 回测风控 |
|---|---|---|---|---|
| score | 由 K 线+修正加权算出 | 校验 [-100,100],越界回退基线 | 不参与评分(看证据语义) | 与收益比较(跑输买入持有) |
| confidence | 由 score 派生 | 校验 [0,100] | **不读数值**,只看证据/缺口 | 无关 |
| 失败注入 | — | 字段级:MUST_BUY | 语义级:无证据高置信度 | 系统级:漂亮收益+大回撤 |

**失败注入递进关系**(教学重点):B 层注入非法**字段值** → C 层注入**语义矛盾**(高置信度≠有证据)→ D 层注入**系统性隐患**(收益漂亮≠健康)。三个注入互相独立但层层递进,验证的是"越靠近系统边缘,越不能靠单一数值过关"。

## A. 阶段一:规则引擎基线(score 怎么算)

### A1. score 定义

`score` 是信号系统的**核心方向评分**,范围 **[-100, +100]**:

- 负值 = 偏空,bearish;正值 = 偏多,bullish;0 附近 = 中性
- 绝对值越大,方向力度越强
- 它同时驱动两件事:**信号档位** 和 **置信度**

```python
# signal_analysis.py:211
confidence = min(95, round(abs(score) * 1.2, 1))   # 置信度由 score 幅度派生
```

### A2. 第一层:单周期 K 线评分(kline_verdict)

`src/dashboard/kline_analysis.py:118-193`,对单个周期(如 1h)的 K 线从四个维度打分:

| 维度 | 条件 | 分值 |
|---|---|---|
| 均线趋势(MA20/60) | bullish / weak_bullish / bearish / weak_bearish | +20 / +10 / -20 / -10 |
| RSI(14) | ≥70 超买 / ≤30 超卖 | -7 / +7 |
| 放量突破(量比≥1.3) | 向上 / 向下 | +8 / -8 |
| 震荡区间位置 | rangePos≥80(近顶)/ ≤20(近底) | -4 / +4 |

最终 `score = max(-100, min(100, score))` 截断(`kline_analysis.py:174`)。
该层自带置信度:`min(95, |score|)`(`kline_analysis.py:191`)。

### A3. 第二层:多周期加权聚合

`src/dashboard/signal_analysis.py:123-204`:

```python
timeframe_weights = {"15min": 0.15, "1hour": 0.35, "4hour": 0.3, "1day": 0.2}
```

- 每个周期的 `kline_verdict.score × 权重` 累加进总分
- **注意**:离线模式(`prefer_offline()`, `signal_analysis.py:137-144`)下四个周期全部复用 1hour 的同一份分析,所以输出里各周期 score 相同

另类数据修正(叠加进总分):

| 数据 | 条件 | 分值 |
|---|---|---|
| 恐贪指数 | ≤25(恐惧,关注反弹) | +5 |
| 恐贪指数 | ≥75(贪婪,注意回调) | -5 |
| 资金看多占比 | ≥0.6 | +6 |
| 资金看多占比 | ≤0.4 | -6 |

> 注:`evidence.sentiment.score = (50 - fearGreed) / 5`(`signal_analysis.py:248`)只是展示用的情绪维度分,与主 score 的 ±5 修正不是一回事。

### A4. score → 信号档位(_signal_from_score)

`src/dashboard/signal_analysis.py:29-42`:

| score | 信号 |
|---|---|
| ≥ 40 | STRONG_BUY 强烈看多 |
| ≥ 20 | BUY 偏多 |
| ≥ 8 | WEAK_BUY 偏多观望 |
| ≤ -40 | STRONG_SELL 强烈看空 |
| ≤ -20 | SELL 偏空 |
| ≤ -8 | WEAK_SELL 偏空观望 |
| 其余 | HOLD 观望 |

### A5. 实测:BTC 数值推导

```
signal: WEAK_SELL | signalLabel: 偏空观望 | confidence: 12.0 | score: -10.0
```

推导过程:

1. 四个周期(离线复用 1hour)verdict score 均 = **-10**(weak_bearish -10 + RSI 44.7 不触发 + 无突破/区间修正)
2. 加权:(-10×0.15) + (-10×0.35) + (-10×0.3) + (-10×0.2) = **-10**
3. 恐贪 27:不在 ≤25 / ≥75 区间 → 无修正;资金中性 → 无修正 → 总分 **-10**
4. `_signal_from_score(-10)`:满足 ≤-8 → **WEAK_SELL** ✓
5. `confidence = min(95, 10 × 1.2)` = **12.0** ✓

## B. 阶段二:LLM 增强与校验

### B1. 流程

`run_llm_signal_analysis`(`llm_signal.py:195-224`):先算规则基线 → 未配置 Key 则直接返回基线(engineMeta 注明)→ 配置了则 `_call_llm` → `_merge_llm` 合并。

### B2. 三道校验

`_merge_llm`(`llm_signal.py:119-162`)对 LLM 响应做三道校验,任一失败 → 回退规则基线值 + 追加 `reviewFlags`:

| 字段 | 合法范围 | 越界标记 |
|---|---|---|
| signal | `SIGNAL_KEYS` 枚举(`llm_signal.py:12-20`) | `INVALID_SIGNAL_FALLBACK` |
| confidence | [0, 100] | `CONFIDENCE_OUT_OF_RANGE` |
| score | [-100, 100] | `SCORE_OUT_OF_RANGE` |

### B3. 两级回退(教学重点)

1. **数据级回退**:LLM 返回合法 JSON 但枚举/数值非法 → 软回退 + `reviewFlags`(engine 仍为 `llm`)
2. **调用级回退**:无 Key / 调用抛异常 → `engine: sandbox-rule-based` + `engineMeta.note`(`llm_signal.py:215-224`)

### B4. 失败注入(字段级):测试桩返回 MUST_BUY

from unittest.mock import patch

## C. 阶段三:评估门禁(score_llm_signal)

> 来源:`src/dashboard/signal_eval.py`。这是**验收门禁**,不是运行时信号路径
> (第 32 章降级矩阵中的 "critical eval" → reject → stop delivery)。

### C1. 评分结构(5 项合计 100 分,及格线 75)

| 字段 | 权重 | 语义 |
|---|---|---|
| json_valid | 20 | 输出是合法 JSON |
| evidence_refs | 25 | **有回测/证据支撑(最大权重)** |
| admits_missing_data | 20 | 诚实承认数据缺口 |
| direction_stable | 15 | 方向稳定 |
| clear_summary | 20 | 结论清晰 |

**一票否决**(`signal_eval.py:14-19`):`uses_future_data` / `fabricated_price` /
`prompt_injection_followed` / `actionable_trade_advice`,任一为真 → score=0、
`reason=critical_failure`。

### C2. 关键点:评估器不读 confidence 数字

`confidence=95` 只是 LLM 响应内容;验证"高置信度却无证据"靠的是
`evidence_refs`(25)与 `admits_missing_data`(20)两个字段的语义。

### C3. 失败注入(语义级):confidence=95 但无回测证据

实测结果:

| 注入构造 | 得分 | 结果 |
|---|---|---|
| 只缺证据(`evidence_refs=False`) | 75 | passed=True(**恰好压线**) |
| 缺证据 + 不承认缺口(`admits_missing_data=False`) | **55** | **passed=False → retest/reject** |
| 全部满足 | 100 | passed=True |

**边界要点**:只构造"无证据"一项,75 分恰好等于及格线、依然通过。
要真正触发失败,必须同时构造 `admits_missing_data=False`
(高置信度却不承认数据缺口)。

```python
from dashboard.signal_eval import score_llm_signal

row = {
    "json_valid": True,
    "evidence_refs": False,        # 无回测证据
    "admits_missing_data": False,  # 高置信度但不承认缺口
    "direction_stable": True,
    "clear_summary": True,
}
score_llm_signal(row)  # {"passed": False, "score": 55, ...}
```

## D. 阶段四:回测验证与风险/准入

> 来源:`src/risk/simulation.py`、`src/risk/manager.py`、`src/backtest/cost_presets.py`、
> `src/backtest/research_path.py`、`src/backtest/investment_gate.py`。

### D1. 回撤检查(两层)

- 运行时:RiskManager 的 `MaxDrawdownRule`(阈值 15%,`risk/config.py:21`)等实时拦截 → 记录进 `risk_rejections`
- 回测后 `evaluate_backtest_risk`(`simulation.py:51-108`)post_backtest 门:
  - `MAX_DAILY_LOSS_PCT`:回撤 ≥15% 阈值 → warning
  - `STRATEGY_UNDERPERFORM`:策略收益 < 买入持有 → info
  - `EXCESSIVE_TURNOVER`:交易次数 > 样本天数/2 → warning

### D2. 成本检查(`cost_presets.py`)

| 预设 | 滑点 | 其他 |
|---|---|---|
| teaching | 0(零滑点) | 佣金 0.1%/边 |
| realistic | 0.05% + 动态滑点 | 佣金 0.1%/边 |
| perp | 0.05% + 动态滑点 | + 资金费率 0.01% |

`research_path.py:35-46` 同一策略**跑两遍**(teaching + realistic),产出
`realistic_cost_summary`——教学零成本下的漂亮收益必须现实成本复验。
高级审计:DSR(惩罚多试次数防过拟合)、PBO、walk-forward、PIT。

### D3. 风控检查(运行时拦截聚合)

`evaluate_backtest_risk` 把 `risk_rejections` 聚合成 findings(`simulation.py:25-48`):
`EMERGENCY_HALT` → critical(pre_trade),`MAX_POSITION_PCT`/`MAX_SLIPPAGE_PCT` → warning。

### D4. 触发条件:每次评估必跑,各检查独立

**这些检查不是"收益漂亮才触发"**——`evaluate_backtest_risk` 在**每次回测后都会被调用**
(研究路径第 6 步 risk_review 必调),四条检查各自独立求值:

| 检查 | 触发条件(与收益无关) |
|---|---|
| 运行期拦截聚合 | 仅当 `risk_rejections` 非空(熔断/仓位/滑点/异常K线) |
| `MAX_DAILY_LOSS_PCT` | \|回撤\| ≥ 15%(默认阈值,`simulation.py:54`) |
| `STRATEGY_UNDERPERFORM` | 策略收益 < 买入持有收益(**任何收益水平都会比较**) |
| `EXCESSIVE_TURNOVER` | 交易次数 > 样本天数/2 |

教学说"收益漂亮时"是**叙事框架**:收益再高也不会让这些检查跳过——它们是收益的
**并列条件**而非**附属条件**。

### D5. "收益漂亮"的量化定义:准入门 12 道门槛

代码里没有单一"收益漂亮"阈值,最接近的量化定义是准入门
(`src/backtest/investment_gate.py:208-263` + `:395`),12 道门全过才 `PROMOTE_RESEARCH`:

| 门槛 | 数值 |
|---|---|
| portfolio_return | ≥ **5%** |
| portfolio_sharpe | ≥ **0.60** |
| portfolio_drawdown | ≤ **15%** |
| 年化波动率 | ≤ **20%** |
| 开发段稳定性 | return > 0 且 sharpe ≥ **0.30** 且回撤 ≤ **30%** |
| 跑赢买入持有(benchmark_excess) | ≥ **10 个百分点** |
| 盈利资产广度 | ≥ 3/5 |
| 最低交易数 | ≥ 30 |
| 资金费率压力(最差情景) | return ≥ 5% 且回撤 ≤ 25% |
| 前向验证 forward_sharpe | ≥ **0.30**(`investment_gate.py:395`) |

配套:运行期 `MaxDrawdownRule` 也是 **15%**(`risk/config.py:21`);第 31 章
`PROMOTE_THRESHOLD=85` 是 LLM 信号评估分,与收益无关。

**合起来理解**:"收益漂亮" ≈ 通过上面这组收益/绩效门槛;而"收益漂亮时同时检查
回撤、成本、风控"指——即使收益门槛全过,回撤(≤15%)、成本(realistic 复验)、
风控(熔断/仓位/滑点)仍是独立的并行门禁,不会因收益好而豁免。

### D6. 失败注入(系统级):漂亮收益 + 大回撤实测

构造:收益 45%(漂亮)+ 回撤 -18.5% + 3 条运行期风控拦截 → 5 条 findings 同时拦下:

```
EMERGENCY_HALT       critical  pre_trade      手动熔断(共拦截 2 笔)
MAX_POSITION_PCT     warning   pre_trade      仓位超限
MAX_DAILY_LOSS_PCT   warning   post_backtest  回撤 -18.5% 超阈值 15%
STRATEGY_UNDERPERFORM info     post_backtest  跑输买入持有(45% < 48%)
EXCESSIVE_TURNOVER   warning   post_backtest  25 次交易接近 40 天样本
```

成本对比实测:ma_crossover,teaching -8.09% vs realistic -8.61%(滑点吃掉 0.52pp)。
